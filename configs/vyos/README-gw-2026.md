# 実験室GWの設定記録（2026年10月8日）

Proxmox `172.20.60.14:8006` のVM100（VyOS 2026.03 / circinus）を指導書の構成へ移行した。設定は保存済み。認証情報を含まないネットワーク設定の抜粋は [gw-2026.commands](gw-2026.commands)。これは認証・基本システム設定を省略した記録であり、単体の復元用設定ではない。

## 接続

| VyOS | Proxmox | アドレス | 役割 |
| --- | --- | --- | --- |
| eth0 / net0 | vmbr3（物理ポートなし） | 10.0.0.1/24 | 模擬外部 |
| eth1 / net1 | vmbr1 / enp2s0f1 | 192.168.1.1/24 | 共通スイッチ |
| eth2 / net2 | vmbr0 / enp2s0f0 | 172.20.60.13/16 | SSH管理専用 |

SSH: `ssh vyos@172.20.60.13`。既存のEd25519鍵で接続確認済み。Proxmox経由なら `ssh -J root@172.20.60.14 vyos@172.20.60.13` も使える。

管理NICの既定MACでは学内側とのARPが成立しなかったため、eth2のMACを従来の `bc:24:11:a9:3f:0d` に設定して疎通を回復した。eth2の識別用hw-idは `bc:24:11:52:1a:99` のままとする。eth0とeth2の実効MACは同じだが、別の隔離されたL2区画に接続しているため混在させない。Proxmoxで今後MACフィルターを有効にする場合は、この実効MACとの整合も確認する。

既存のvmbr2には無線NICの接続があったため、模擬外部には使わない。

## 経路とサービス

- ペアLAN `192.168.21.0/24`～`192.168.26.0/24` への戻り経路を、それぞれ `192.168.1.21`～`.26` に設定。R6未接続時はその経路の先には到達しない。
- 管理用デフォルト経路は `172.20.0.1`。GW自身のシステムDNSは既存の学内DNSを維持。
- IPv4転送はeth1同士、eth1→eth0、eth0→eth1のみ許可。eth2を通る転送とIPv6転送は遮断。
- 共通LANの旧DHCP配布とGWの旧DNS転送を撤去。DHCPは各ペアのLAN内で実験する。
- NAPTルール100は送信元 `192.168.0.0/16`、宛先 `10.0.0.0/24`、出力eth0。第1回用に**無効**として保存。

第2回で有効化:

```text
configure
delete nat source rule 100 disable
commit
save
exit
```

次の班の第1回へ戻すときは、上記のdeleteを `set nat source rule 100 disable` に置き換える。NAPT前後は新しい接続で確認する。

## 教材サーバーの移行

VM101 `lab-files` は `192.168.1.10/24`、GWは `192.168.1.1`、DNSは設計上の `192.168.1.53` へ移行。ゲストのnetplanとProxmoxのcloud-initの両方へ反映した。Proxmoxの共通LAN側も `192.168.1.14/24` に変更済み。

Samba共有は `\\192.168.1.10\maintenance` と `\\192.168.1.10\images`。既存のアカウント・権限は継続する。ファイアウォールの旧LAN許可を共通LANと各ペアLANへ更新し、APTキャッシュの待受も新IPへ移行。TCP/445・3142への接続を確認した。

実験LANを閉じたため、APTキャッシュの学外からの新規取得はこの構成では利用できない。キャッシュの待受確認と上流取得の確認を混同しない。

Proxmox上に試験用R6・端末・外部Webを一時作成して、次を確認した。試験用の名前空間とプロセスは撤去済み。

- GWから模擬外部ホストへの疎通。
- ペアLANの端末から教材サーバーへの往復通信。
- NAPT無効時は外部HTTPがタイムアウトし、有効時は成功。
- 外部Web側で送信元が `10.0.0.1` に変換されていること。
- ペアLANから学内管理側 `172.20.60.14` への転送が遮断されること。
- 最後にNAPTを無効へ戻して保存し、通常のSSHで再接続。
